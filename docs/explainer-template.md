# Explainer Template

> **DRAFT v0.1. Not yet binding.** This becomes binding when the owner removes this notice.
> Defines page templates, writing rules, the verifier checklist, and the output schema for Tier 2 and Tier 1 content.
> The schema here is the human-readable spec. The authoritative version is the Pydantic models in `src/schemas/`, exported to `schemas/`. If they disagree, stop and ask.

## Who fills what

| Filled by code (from official data) | Written by the drafter model | Added by the human reviewer |
|---|---|---|
| bill ID, title, sponsors, status, dates, actions, vote counts, individual votes, fiscal note figures, source links, tier, rules fired, `rule_version` | summary, provisions, current-law comparison, unknowns, supporter/opponent summaries (from collected statements), glossary | `reviewed_by`, `reviewed_at`, corrections, conflict disclosures |

The drafter never writes a number, date, name, or vote. Where text needs one, it uses a placeholder token such as `{fiscal.total_fy1}` that code fills in. A draft containing a digit outside a token or a section cite fails verification.

## Tier 2 page (in this order)

1. **Title and status** (code)
2. **At a glance** (code): sponsors, introduced date, current status, last action, effective date if any
3. **What the bill does**: one-sentence summary (Explanation, cited)
4. **Main provisions**: 2 to 6 items, each one sentence or two, each with a section cite (Explanation)
5. **Cost**: figures from the fiscal note (Fact). If none: "No fiscal note has been published for this bill as of {last_checked}."
6. **Votes**: roll-call totals per stage, link to full vote table. Voice votes noted as such (Fact)
7. **Unknowns**: 1 to 4 items. If none: "The bill text and fiscal note answer the questions we checked." (Unknowns)
8. **Sources** and **Last checked** (code)
9. **Reviewed by [name] on [date]** (reviewer)

## Tier 1 page (in this order)

All Tier 2 sections, plus, inserted after section 4:

- **Current law and what would change**: for each main provision, what the law says now and what the bill changes, each with a section cite and, for current law, a W.S. statute cite.
- **Who the bill applies to**: only groups named or defined in the bill text, with section cites. No estimates of effects.
- **Supporters and opponents** (see rules below)
- **Amendment history**: adopted amendments with dates and a one-line plain description each, cited to the amendment.
- **Glossary**: optional, terms used in the bill.

And at the end, before Sources:

- **Why this bill got a full explainer**: generated by code from the triage log. Example: "This bill qualified under rule T1-C (close recorded vote) on {date}, rules version {rule_version}." No other wording.

## Supporters and opponents rules

- Two sections, `supporters` and `opponents`, using the identical component, format, and limits: up to **[DECIDE] 3** arguments each, each up to **[DECIDE] 50** words.
- Each argument is a paraphrase of a public statement, attributed to a named person or organization, with a link and date. Short quoted phrases only.
- No statement found for a side: "We found no public statements {supporting|opposing} this bill as of {last_checked}." Never pad.
- **`argument_order`** is set by code, not by the drafter: supporters first when the bill number is even, opponents first when the bill number is odd. The same rule applies to every bill.
- Legislators' floor statements count as public statements. Sponsors are not automatically listed as supporters.

## Writing rules

- Plain English. Target reading level grade 8 **[DECIDE] measure with which tool**. Sentences under about 25 words.
- Present tense for what the bill does: "The bill requires…", "Section 3 changes…"
- Every Explanation sentence ends with or contains a section cite: "(Sec. 3)".
- Use "would" for bills not yet law and present tense for enacted bills. Code supplies the status, so the drafter receives it as input.
- No judgment words. Banned list (extendable): *important, major, significant, controversial, landmark, sweeping, radical, common-sense, extreme, reckless, fair, unfair, good, bad, harmful, beneficial, crucial, critical, unfortunately, fortunately, merely, only (as minimizer), just (as minimizer), finally*.
- No predictions ("will likely", "could lead to", "is expected to") unless quoting a fiscal note, attributed: "The fiscal note estimates…"
- No motives ("aims to", "seeks to", "in an effort to", "intended to") unless the bill states its own purpose, cited.
- No recommendations or calls to action other than links to official sources.
- No second person "you" effects ("you'll pay less"). Describe what the bill says.
- Identical wording patterns for every party, legislator, and organization.

## Verifier checklist

The verifier is a separate model call with its own prompt, plus code checks. Any failure fails the item.

**Code checks**
1. Output matches the schema exactly.
2. Every Explanation item has at least one section cite, and every cited section exists in the bill text.
3. No digits outside tokens and section or statute cites.
4. Every token resolves to a value in the official data.
5. No banned words or phrases outside attributed quotations.
6. Supporter and opponent sections each obey the count and length limits; each argument has an attribution, URL, and date.
7. `argument_order` matches the code rule.
8. Quoted text from third parties is under **[DECIDE] 15** words per quote.

**Model checks** (each statement reviewed against the cited section text)
9. The cited section actually supports the statement.
10. The statement does not add effects, predictions, or motives the section doesn't state.
11. Nothing important in a cited section is misstated by omission (for example, an exception left out).
12. Supporter and opponent paraphrases match their linked sources.
13. Tone check: no loaded framing, and the two sides read with equal neutrality.

Every failed statement is deleted, not rewritten by the verifier. The item then returns to the drafter or the human.

Required on every published item: `bill_id`, `tier`, `rule_version`, `reviewed_by`, `reviewed_at`, `verifier_passed`, `last_checked`, `sources`.

Tier 2 items omit `current_law`, `applies_to`, `supporters`, `opponents`, `argument_order`, `no_statements_found`, `amendments`, and `glossary`. Tier 3 items are listings with only the code-filled fields, plus `sources`, `last_checked`, and the required review fields. Under `CLAUDE.md` rule 3, Tier 3 listings also need a reviewer, review date, and passing verifier (code checks only). A reviewer may approve Tier 3 listings in a batch: one approval covers every listing in that batch, and each listing records the same `reviewed_by` and `reviewed_at`. Batch approval is not allowed for Tier 2 or Tier 1.

Vote type is `roll_call` or `voice`. Voice votes carry no counts and no individual votes. Individual roll-call votes live in separate files, one per roll call, under `content/votes/`.
